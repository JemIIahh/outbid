# Outbid Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A buyer agent runs a sealed-bid auction among seller agents using Remesso signed invoices, pays the winner from the owner's on-chain spending policy, and the winner delivers only after verifying the payment, with every step on a live ledger.

**Architecture:** An in-process typed event bus connects a buyer round runner and several seller agents, each with its own key and `remesso-sdk` client. All chain activity runs on the SDK's local Celo fork (`remesso-sdk/dev`). A small HTTP server streams bus events (SSE) to a single-page ledger.

**Tech Stack:** TypeScript (strict, ESM), Node 22, `remesso-sdk@0.3.1`, viem, vitest, `@anthropic-ai/sdk`, anvil 1.5.1.

**Spec:** `docs/superpowers/specs/2026-10-28-outbid-design.md`

## Global Constraints

- Node >= 20 (SDK engine floor; machine has 22), TypeScript `strict`, ESM, pnpm.
- One token: `USDT` (6 decimals; `0.05` USDT = `50_000n`). Amounts cross module boundaries as decimal strings.
- Local fork by default via `startDev` from `remesso-sdk/dev`. Mainnet only behind an explicit flag (Task 12). Never fund or use dev keys on a real network.
- Bid validity: `expiresAt = now + 120` seconds. The SDK refuses to start a payment whose invoice has under 60 s left (`START_MARGIN_S`), so a 60 s bid is dead on arrival; 120 s leaves the buyer a 60 s window. Invoices are offline (`invoices.sign`, `requestId: ""`) and paid with `funding: "policy"`.
- Every bid names the owner's address as `payer` (the funds owner), not the buyer agent's.
- Fulfilment claims must be unique on **both** `invoiceId` and the payment's `eventId`.
- Finality (my call): jobs priced <= `0.10` USDT deliver on `included`; dearer jobs wait for `finalized`.
- Policy (my call): `perPayment "0.50"`, `perDay "5.00"`, `days 1`, `budget "5"`, `recipients` = every seller address.
- `ANTHROPIC_API_KEY` is optional: absent means deterministic stub skills/grader. Model ids: `claude-haiku-5-5`, `claude-sonnet-5-5`.
- No real-money spend without the owner's explicit go-ahead.
- Commit only when the owner asks. Never add Claude attribution lines to commits or PRs.

## Review Focus

- A bid priced above the policy's `perPayment` cap: the payment is refused and the buyer must fall back to the next-ranked bid, not abort and not retry the same one. (Task 7)
- The same payment (`txHash`) replayed to claim a second order, or `fulfil` called twice: work runs once. (Task 4)
- Policy revoked between bid and payment: the round aborts, nobody delivers, `policy.revoked` is emitted. (Task 7)
- A forged or altered invoice (wrong payer, wrong recipient, tampered amount, signed by a different key): rejected before any money moves. (Task 6)
- A payment that comes back `pending`: resume the same payment; never pay a different bid after an uncertain send. (Task 7)
